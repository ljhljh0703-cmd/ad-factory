# 광고 공장 엔진

기획부터 대본, 심사, 녹화, 편집, 녹화본 대조, 사람 검토, 게시 승인, 성과 보고까지를 단계로 쪼개 한 대기열에서 돌린다. 앱(app/)은 이 엔진의 명령만 부른다.

## 실행

```
cd engine
python3 -m adf pipelines                       # 묶음 목록
python3 -m adf pipeline 심사 run=J20 set=dev    # 묶음 넣기
python3 -m adf run                             # 대기열 돌리기
python3 -m adf dashboard --json                # 앱이 읽는 요약
```

앱: `cd app && npm install && npm start` (엔진 폴더 위치는 ADF_ROOT, 파이썬은 ADF_PYTHON 으로 바꿀 수 있다)

## 작업 기록

작업 하나는 `runs/jobs/B0001/job.json` 하나다. 입력 파일과 해시, 산출 파일과 해시, 모델과 제공자, 토큰 수, 걸린 시간, 상태가 남는다. 상태는 대기, 실행, 외부응답대기, 사람확인대기, 완료, 실패, 막음 중 하나다. 앞 작업이 완료여야 다음 작업이 돈다.

## 모델 제공자

| 제공자 | 쓰는 때 | 토큰 |
|---|---|---|
| api | ANTHROPIC_API_KEY 가 있을 때 | 응답의 usage 값 |
| session | 키가 없을 때. 요청문을 작업 폴더에 두고 응답 파일을 기다린다 | 글자 수로 어림(추정 표시) |
| replay | 예전 응답을 다시 쓴다. 회귀 검사에서 돈을 쓰지 않을 때 | 0 |

요청문이 바뀌면 예전 응답은 `.old` 로 밀어 두고 새 응답을 기다린다. 가격은 `engine/prices.json` 에 확인한 값만 적는다. 없으면 달러는 비워 둔다.

## 게임 붙이기

`adapters/<게임>/adapter.json` 하나와 드라이버 하나면 된다.

| 부분 | 적는 것 | 젤리 패닉 | 보석타워 |
|---|---|---|---|
| 규칙 | 장면을 찾는 방법 | 코어를 node로 돌림(빠름) | 공개판을 6배속으로 끝까지 둠(느림) |
| 입력 | 한 수 두는 법 | 조각 끌어 놓기 | 칸 탭, 보석 고르기, 조합 |
| 화면 | 뷰포트, 찍는 배율, 자르는 곳, 영상 안 게임 자리 | 390×844, 2.769배 | 같음, 자르는 곳만 다름 |
| 사실표 | 사실표 파일과 대조할 소스 | 공개판 index.html | web/*.js |

사실표(`game/<게임>.json`)가 있으면 대본 생성과 심사도 그 게임으로 돈다. 대본 묶음에 `game=gem-tower` 를 넣으면 되고, 생성분 심사는 회차에 남은 게임 이름을 따른다.

드라이버는 `url(seed)`, `boot(T)`, `step(T, i, 바꿀_수)` 세 함수를 낸다. 녹화기(`engine/recorder.mjs`)가 가상 시각으로 1/30초씩 멈춰 가며 찍는다.

결정론 확인 방법은 게임마다 다르다. 젤리 패닉은 페이지 안 그림자 판 점수와 화면 점수를 수마다 맞춘다. 보석타워는 게임이 직접 내는 상태 해시를 수마다 남기고, 장면 앞 순간은 게임의 조작 기록으로 되돌린다(해시가 다르면 녹화하지 않음).

## 사실표 자동 대조

`adapter.json` 의 「자동_대조」에 안내 함수, 판 끝 문구 변수, 화면 요소 id, 규칙 숫자 정규식을 적는다. 어긋나면 심사 묶음 첫 단계에서 막는다. 시험은 `python3 tests/test_factcheck.py`. 지금까지 사람이 고친 사실표 판 6개를 하나씩 되돌려 5개를 잡는다. 못 잡는 하나는 뜻을 읽어야 하는 수정(없는 것 목록, 끝나는 경우 설명)이다.

## 회귀 감시

기준표, 사실표, 요청문 틀, 규칙 코드, 모델, 검토 묶음의 해시를 지문으로 둔다. 지문이 바뀌면 dev 와 review 묶음을 다시 심사하고, 반려를 통과시킨 것이 하나라도 있으면 막는다. 숨긴 묶음은 배포 전 확인(`regress check release=true`)에서만 돈다.

## 사람 검토

심사에서 「사람 확인」으로 끝난 소재가 대기열로 간다. 결정에는 이유가 꼭 있어야 하고, 반려는 걸린 조건을 적어야 한다. 결정한 소재는 `eval/review/review.jsonl` 로 들어가 다음 회귀부터 함께 돈다.

## 게시

요청할 때 심사 통과, 녹화본 대조 통과, 게시 허락된 게임, 링크 꼬리표, AI 표시를 자동으로 본다. 승인은 사람 이름으로만 받고, 승인할 때의 영상·글 해시를 묶는다. 실행할 때 해시가 다르면 막는다. 채널 토큰이 없으면 연습으로만 기록한다. 감사 기록은 줄마다 앞 줄 해시를 품는다.

## 시험

```
python3 tests/test_factcheck.py   # 사실표 대조
python3 tests/test_perf.py        # 소재 피로
python3 tests/test_publish.py     # 게시 관문(임시 폴더에서)
node ../adapters/jelly-panic/tests/track_test.mjs   # 익명 기록(브라우저)
cd ../app && xvfb-run -a node test/smoke.mjs        # 앱 화면
```

## 단계 넣기

`adf/stages.py` 에 `@stage("이름")` 함수 하나를 더한다. 입력은 `job.input`, 산출은 `job.output` 으로 남기고, 관문에 걸리면 `Blocked`, 사람이나 외부 응답을 기다리면 `Wait` 를 던진다. 같은 작업을 다시 돌려도 결과가 같게 쓴다.
