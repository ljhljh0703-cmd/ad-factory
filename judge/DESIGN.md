# 광고 소재 심사기 설계 (1단계 4번)

## 1. 세 층으로 거른다

| 층 | 하는 일 | 판정 |
|---|---|---|
| ① 규칙 검사 | 문자열·규격으로 확실히 걸리는 것: 숫자·순위·평점, 경품·보상 낱말, 등급 표시, 화면비, 게임 이름 위치, 자막, 끝 할 일 수, 사실표의 「없는 것」 | 걸리면 바로 반려. 사유 문장은 정해 둔 문안 |
| ② AI 판정 | 기준표 조건마다 위반인지 아닌지(둘 중 하나)와 근거가 된 대본 구절, 사유 문장 | 같은 요청문으로 두 번 판정 |
| ③ 사람 확인 | AI가 스스로 「사람 확인」을 낸 것, 두 번의 판정이 엇갈린 것 | 작가가 최종. 뒤집은 판정은 기록해 기준 고칠 근거로 씀(1단계 5번) |

①이 확실한 것을 먼저 치우면 ②는 장면이 게임에 있는지, 후기 흉내인지처럼 읽고 판단해야 하는 것에 집중한다.

## 2. 업계 권장 방식과 맞춘 곳

| 권장 방식 | 출처 | 여기서 |
|---|---|---|
| 1~5점 점수 대신 통과·위반 둘 중 하나, 위반에는 이유를 반드시 씀 | Tian Pan, LLM-as-judge 정리(2025) · Arize 평가기 권장 사항 | 조건마다 위반 여부 + 대본 구절 인용 + 「무엇이·어디에·어떻게」 사유 문장 |
| 복잡한 판단은 하위 조건으로 쪼갬 | Arize | 기준표 G1~G8 · R1~R11 조건별 판정, 마지막 판정은 조건을 합쳐 계산 |
| 판정자는 생성기와 다른 모델 | Arize(자기 결과를 좋게 보는 치우침) | 생성은 Opus, 판정은 Sonnet. 다른 회사 모델은 아직 못 붙임(남은 한계) |
| 사람이 정답 붙인 시험 묶음과 맞춰 보고 맞을 때까지 요청문을 고침, 90% 이상 목표 | Tian Pan · Arize | dev 46개로 고치고, holdout 28개는 판을 확정할 때 한 번만 |
| 일치율만 보지 말고 정밀도·재현율을 따로 | Tian Pan(통과·위반 비율이 기울면 일치율이 속임) | 반려 재현율(위반을 놓치지 않음)을 첫째 지표로. 놓친 위반은 이름을 붙여 목록으로 |
| 신뢰도가 애매하면 사람 검토로 보냄 | Checkstep 검수 흐름(50~95% 구간은 사람 검토) | 두 번 판정이 엇갈리거나 AI가 「사람 확인」을 내면 사람에게 |
| 모든 조치를 기록 | Checkstep | 판정마다 기준표 판·요청문 판·모델·회차를 같이 저장 |
| 모델이 자신 있게 틀리는 경우를 먼저 그림 | 토스 AI Engineer(Ads) 공고 | 경계 사례 13개와 「비싼 오류」(반려를 통과시킴) 목록을 따로 셈 |

## 3. 재는 것

- 판정 일치: 통과·반려·사람 확인 셋이 정답과 같은 비율.
- 반려 재현율: 정답이 반려인 것 중 반려나 사람 확인으로 걸러낸 비율. 통과시키면 비싼 오류.
- 반려 정밀도: 반려로 낸 것 중 정답도 반려인 비율.
- 사람 확인 비율: 작가에게 넘어가는 양.
- 조건별 재현율: 어느 반려 조건을 자주 놓치는지.
- 카파: 우연히 맞는 몫을 뺀 일치도.

목표(판정을 확정할 조건): 반려 재현율 100%(비싼 오류 0), 판정 일치 90% 이상, 사람 확인 20% 이하.

## 4. 판본

- 기준표 판 = CRITERIA.md 변경 기록 마지막 날짜.
- 요청문 판 = `prompts/judge-v1.md` 처럼 파일 이름에 붙임. 고치면 v2 로 새 파일.
- 회차마다 `runs/<회차>/run.json` 에 기준표 판, 요청문 판, 모델, 판정 횟수를 적는다.

## 5. 남은 한계

- 판정과 생성이 같은 회사 모델이다. 다른 회사 모델을 붙이면 치우침을 한 번 더 걸러낼 수 있다.
- 정답을 붙인 사람이 기준표를 쓴 쪽이다. 작가 확인을 거치면 정답 품질이 올라간다.
